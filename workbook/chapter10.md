# Chapter 10 독자 워크북

> **검증 기준 버전**
>
> 이 장의 자동 검증 기준은 **PostgreSQL 16**입니다. PostgreSQL 16의 다중 컬럼 B-tree에서는 선두 컬럼 제약이 없으면 후행 컬럼 조건만으로 탐색 범위를 줄이기 어렵습니다. **B-tree Skip Scan은 PostgreSQL 18에서 추가**되었으므로, PostgreSQL 18 이상에서는 동일 SQL의 계획이 달라질 수 있습니다. 실습 결과에는 서버 버전을 함께 기록합니다.

**Chapter 07·08 시작 기준**

`course_project`의 `students / instructors / courses / enrollments = 3 / 2 / 3 / 5`, 상태는 `신청 2 / 수강중 1 / 완료 1 / 취소 1`이어야 합니다.  
`course_project.enrollments.recorded_amount`는 `NUMERIC(12,0)`이며, 전체 기록 금액은 `590000`, 활성 신청은 `3건 / 340000`, 취소 제외 이력은 `4건 / 440000`입니다.  
기준 신청은 `1001 = 완료 / 100000`, `1004 = 취소 / 150000`, `1005 = 신청 / 120000`이고 `uq_course_enrollments_active`가 존재해야 합니다. 또한 Chapter 07의 **명명 제약조건 15개와 `NOT NULL` 열 20개**가 유지되어야 합니다. Chapter 10은 이 상태를 읽기만 하고 변경하지 않습니다.

## 21. 권장 해설

### 자동 인덱스

```text
PRIMARY KEY와 UNIQUE는 고유 인덱스를 자동 생성한다.
FOREIGN KEY 자식 컬럼에는 자동 인덱스가 생성되지 않는다.
```

### 계획 해석

```text
cost는 상대 비용이다.
rows는 예상 행 수이고 actual rows는 실제 행 수이다.
Filter는 행을 읽은 뒤 적용한 조건이고 Index Cond는 인덱스 탐색 조건이다.
Seq Scan은 많은 행이 필요할 때 합리적일 수 있다.
```

### 실험 통제

```text
같은 데이터, 같은 통계, 같은 SQL을 사용하고 인덱스 존재 여부만 바꾼다.
EXPLAIN ANALYZE와 별도로 결과 행 수를 검증한다.
```

### 복합 인덱스

```text
선두 컬럼이 일반적으로 중요하지만 PostgreSQL은 비용에 따라 PostgreSQL 18+ Skip Scan을 선택할 수 있다.
status 단독 조건은 반환 비율이 높아 Seq Scan이 합리적일 가능성이 크다.
```

### 운영 환경

```text
실습에서는 일반 CREATE INDEX를 사용한다.
운영에서는 잠금과 작업 시간을 확인하고 필요하면 CONCURRENTLY를 검토한다.
CONCURRENTLY는 트랜잭션 블록 안에서 실행할 수 없다.
```

### 사용 통계

```text
idx_scan=0만으로 삭제하지 않는다.
통계 기간, 제약조건 역할, 중요하지만 드문 워크로드와 크기를 함께 본다.
```
