| `ORDER BY`가 없으면 순서가 보장되지 않음을 이해했는가? |  |
| 내부 식별자와 업무 식별자를 구분할 수 있는가? |  |
| 기본키와 외래키의 역할을 설명할 수 있는가? |  |
| 외래키 값이 반복될 수 있음을 이해했는가? |  |
| 데이터 타입을 값의 모양만으로 결정하지 않았는가? |  |
| AI 구조를 다섯 질문으로 검토할 수 있는가? |  |

체크하지 못한 항목이 있다면 해당 활동으로 돌아가 다시 확인해 보세요.

## 16. 권장 해설

### 클라이언트와 DBMS

```text
DBeaver
→ PostgreSQL에 접속해 SQL을 보내고 결과를 보여 주는 클라이언트

PostgreSQL
→ 데이터를 저장하고 SQL을 실행하는 DBMS
```

### PostgreSQL 계층

```text
서버
→ 데이터베이스
→ 스키마
→ 테이블과 같은 객체
```

### 테이블과 조회 결과

```text
테이블
→ 데이터를 저장하는 구조

조회 결과
→ SQL의 조건·연결·계산으로 만들어진 결과 집합
```

### 식별자

```text
내부 식별자
→ DB 내부에서 행을 안정적으로 구분

업무 식별자
→ 현실의 업무에서 대상을 식별
```

### 기본키와 외래키

```text
기본키
→ 자신의 테이블에서 행을 고유하게 구분

외래키
→ 참조 대상 키와 연결
```

외래키 값은 1:N 관계에서 반복될 수 있으며, 별도의 `NOT NULL`과 `UNIQUE` 규칙이 있는지에 따라 NULL과 중복 허용 여부가 달라집니다. 실제로 존재하지 않는 참조를 DBMS가 막으려면 `FOREIGN KEY` 제약조건이 설정되어 있어야 합니다.

### AI 구조 검토

```text
한 행의 의미
→ 기본키
→ 참조 관계
→ 서로 다른 데이터의 혼합
→ 타입과 필수 여부
```

AI가 만든 SQL이 실행되더라도 이 다섯 기준을 만족한다고 자동으로 보장되지는 않습니다.
