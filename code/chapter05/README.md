# Chapter 05 실습 코드

## 요구사항에서 데이터 모델과 ERD 만들기

이 폴더는 도서 대여 시스템의 모델을 PostgreSQL 구조와 작은 샘플 데이터로 확인하는 SQL 파일을 관리합니다.

---

## 파일 목록

| 파일 | 시작 상태 | 완료 상태 | 반복 실행 |
| --- | --- | --- | --- |
| `01_library_schema.sql` | 세 테이블 없음 | 빈 테이블 3개 | 한 번 |
| `02_library_seed.sql` | 세 테이블이 모두 비어 있음 | 회원 3·도서 3·대여 4 | 한 번 |
| `03_library_validation.sql` | 샘플 입력 완료 | 구조·관계 검증 | 가능 |
| `reset_library.sql` | 어떤 실습 상태 | 세 테이블 삭제 | 필요할 때만 |
| `library_schema.sql` | 세 테이블 없음 | 번호 생성 파일과 동일 | 호환용 |
| `library_seed.sql` | 세 테이블이 모두 비어 있음 | 번호 입력 파일과 동일 | 호환용 |
| `library_validation.sql` | 샘플 입력 완료 | 번호 검증 파일과 동일 | 호환용 |

처음 학습하는 독자는 번호 파일을 사용합니다. 기존 `library_*.sql`은 이전 링크와 강의 자료 호환을 위해 실행 가능한 상태로 유지합니다.

> 번호 파일과 호환 파일을 모두 실행하지 않습니다. 같은 역할의 파일 중 하나만 선택합니다.

## 권장 실행 순서

```text
현재 연결 확인
→ 01_library_schema.sql
→ 02_library_seed.sql
→ 03_library_validation.sql
```

처음부터 다시 시작할 때는 다음 순서를 사용합니다.

```text
reset_library.sql
→ 01_library_schema.sql
→ 02_library_seed.sql
→ 03_library_validation.sql
```

## 공통 실행 원칙

```text
1. ai_database_book 연결인지 확인한다.
2. 현재 사용자와 search_path를 확인한다.
3. Auto-commit 상태를 확인한다.
4. 파일의 시작 상태를 확인한다.
5. 번호 파일과 호환 파일을 중복 실행하지 않는다.
6. 실행 후 행 수와 검증 메시지를 확인한다.
```

현재 스키마는 환경에 따라 `public`이 아닐 수 있습니다. SQL은 `public.members`처럼 스키마를 명시하므로 `current_schema() = public`을 실행 조건으로 강제하지 않습니다.

## 모델 범위

```text
members 한 행
→ 회원 한 명

books 한 행
→ 이 장에서 대여 대상으로 취급하는 간소화된 도서 항목 한 건

loans 한 행
→ 특정 회원이 특정 도서를 대여한 사건 한 건
```

이 장에서는 다음을 단순화합니다.

```text
동일 ISBN의 실제 복본(copy) 구분
한 도서의 여러 저자
회원 최대 대여 권수
연체 정책
회원·도서 삭제 정책
동시 활성 대여 차단
```

이메일과 ISBN의 고유성은 미확정이므로 `UNIQUE`를 적용하지 않습니다. ISBN이 없는 도서를 허용할지도 미확정이므로 Chapter 05의 `isbn`은 `NULL`을 허용합니다. 날짜 선후 관계와 동시 활성 대여 제약은 Chapter 06에서 보완합니다.

## 테이블 구조

```sql
CREATE TABLE public.members (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL,
    joined_at DATE NOT NULL
);

CREATE TABLE public.books (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    author VARCHAR(100) NOT NULL,
    published_year INTEGER,
    isbn VARCHAR(20)
);

CREATE TABLE public.loans (
    id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    member_id INTEGER NOT NULL REFERENCES public.members(id),
    book_id INTEGER NOT NULL REFERENCES public.books(id),
    borrowed_at DATE NOT NULL,
    due_at DATE NOT NULL,
    returned_at DATE
);
```

생성 순서:

```text
members
→ books
→ loans
```

`loans`가 부모 테이블을 참조하므로 마지막에 생성합니다.

## 샘플 데이터

```text
members: 101, 102, 103
books: 201, 202, 203
loans: 1001, 1002, 1003, 1004
```

| 대여 ID | 회원 ID | 도서 ID | 대여일 | 실제반납일 |
| ---: | ---: | ---: | --- | --- |
| 1001 | 101 | 201 | 2026-04-01 | 2026-04-02 |
| 1002 | 101 | 202 | 2026-04-02 | NULL |
| 1003 | 102 | 201 | 2026-04-03 | NULL |
| 1004 | 103 | 203 | 2026-04-05 | NULL |

샘플에서 확인할 관계:

```text
회원 101은 두 개의 대여 기록을 가진다.
도서 201은 시간에 따라 두 개의 대여 기록을 가진다.
도서 201의 첫 대여는 반납된 뒤 다음 날 다시 시작된다.
미반납 대여는 3건이다.
모든 대여는 존재하는 회원과 도서를 참조한다.
```

## 파일별 안전 검사

### 01_library_schema.sql

```text
현재 DB = ai_database_book
읽기 전용 연결 아님
public 스키마 존재
public 스키마 USAGE·CREATE 권한
세 테이블이 존재하지 않음
BEGIN으로 생성 작업 시작
members → books → loans 생성
세 테이블 존재·0행 확인
COMMIT
```

세 테이블 생성은 하나의 트랜잭션으로 묶습니다. 중간 생성 오류가 발생하면 일부 테이블만 남은 상태로 완료되지 않도록 합니다.

### 02_library_seed.sql

```text
현재 DB = ai_database_book
읽기 전용 연결 아님
세 테이블 존재
세 테이블의 행 수가 모두 0
BEGIN으로 입력 작업 시작
members 3행·books 3행·loans 4행 입력
IDENTITY 다음 값 104·204·1005로 조정
미반납 3건 확인
회원 101 대여 2건 확인
도서 201 대여 2건 확인
COMMIT
```

전체 입력과 IDENTITY 조정을 하나의 트랜잭션으로 묶어 중간 실패 시 부분 입력 상태가 남지 않도록 합니다.

### 03_library_validation.sql

```text
members = 3
books = 3
loans = 4
미반납 = 3
회원 101의 대여 이력 = 2
도서 201의 대여 이력 = 2
회원 참조 고아 행 = 0
도서 참조 고아 행 = 0
도서 201 시간 순서 오류 = 0
books.isbn NULL 허용 = YES
loans 외래키 = 2개
```

검증이 통과하면 다음 메시지가 표시됩니다.

```text
Chapter 05 library model validation passed
```

### reset_library.sql

```text
현재 DB = ai_database_book
public 스키마 존재
읽기 전용 연결 아님
public.loans → public.books → public.members 순서로 삭제
```

현재 스키마 값과 관계없이 스키마를 명시한 세 테이블만 삭제합니다.

## 요구사항과 구현 연결

| 요구사항 | 구조 | 검증 증거 |
| --- | --- | --- |
| 회원 관리 | `public.members` | 3행 저장 |
| 도서 관리 | `public.books` | 3행 저장 |
| 반복 대여 사건 | `public.loans` | 4행 저장 |
| 대여와 회원 연결 | `loans.member_id` | 회원 101 대여 2건 |
| 대여와 도서 연결 | `loans.book_id` | 도서 201 대여 2건 |
| 미반납 상태 | `returned_at IS NULL` | 3건 |
| 참조 무결성 | 외래키 | 고아 참조 0건 |

ERD의 `1:N` 관계는 시간 전체의 반복 이력을 표현합니다. 같은 시점에 활성 대여가 하나만 있어야 한다는 업무 규칙은 별도 제약이며 Chapter 06에서 검토합니다.

## 주의 사항

```text
- 현재 데이터베이스와 실행 파일을 확인한다.
- current_schema가 public이 아니어도 스키마 명시 SQL을 사용한다.
- 번호 파일과 호환 파일을 중복 실행하지 않는다.
- 생성 파일은 기존 테이블을 자동 삭제하지 않는다.
- 입력 파일은 비어 있는 테이블에서만 실행한다.
- reset_library.sql은 모든 Chapter 05 데이터를 삭제한다.
- 이메일·ISBN 고유성을 샘플 값만 보고 확정하지 않는다.
- JOIN은 관계 확인용이며 상세 문법은 Chapter 08에서 학습한다.
- 제약조건 실패 테스트와 ALTER TABLE은 Chapter 06에서 진행한다.
```
